# 真机测试清单（REDMI Turbo 4 / HyperOS 3.0.304.0 / Android 16）

> 本机没有连接手机，所以下面每一项都需要你在真机上跑一遍。建议按顺序做，遇到 ❌ 记下「第几步 + 现象 + logcat 片段」反馈给我。
> 传输/安装见 README 第 2 节。测试时可以先用 ADB 连上，方便看日志：
>
> ```powershell
> cd F:\deepseek-harness\default-workspace\ultra-dim
> .sdk\platform-tools\adb.exe devices            # 应该能看到设备
> .sdk\platform-tools\adb.exe logcat -c
> .sdk\platform-tools\adb.exe logcat -s UltraDim:V AndroidRuntime:E
> ```

## A. 安装与启动

| # | 检查点 | 期望 | 结果 |
|---|---|---|---|
| A1 | 安装 APK | 安装成功，桌面出现「极暗」图标（深色新月） | ☐ |
| A2 | 点开应用 | 1 秒内出现主界面，无闪退 | ☐ |
| A3 | 主界面文字/布局 | 「极暗」标题、状态胶囊「● 已关闭」、4 张卡片、底部机型信息（应为 REDMI Turbo 4 / Android 16） | ☐ |

**如果 A2 闪退**：把 `adb logcat -s AndroidRuntime:E` 里 `FATAL EXCEPTION` 那一段（到 `Caused by` 结束）贴给我。

## C. 核心压暗功能（最关键）

| # | 检查点 | 期望 | 结果 |
|---|---|---|---|
| C1 | 打开「启用遮罩」开关 | 屏幕立刻变暗（默认 40%），通知栏出现「极暗 · 40%」，状态胶囊「● 运行中」 | ☐ |
| C2 | 主滑条从 0 拖到 80% | 亮度平滑变化，无闪烁、无跳变 | ☐ |
| C3 | 拖到 80% 时点桌面图标 / 滑动桌面 | **触摸仍然可用**（这是 0.8 阈值的关键验证） | ☐ |
| C4 | 点 `+1%` × 5 次 | 每次 +1%，数字与亮度同步 | ☐ |
| C5 | 点预设 `20%` | 跳到 20% | ☐ |
| C6 | 「上限」选 `65%` | 滑条最大只能拖到 65%，超过的当前值被压到 65% | ☐ |
| C7 | 覆盖范围：下拉通知栏、看状态栏、看导航栏/手势条 | 状态栏和导航栏也被压暗（无亮边、无缝隙）；刘海/挖孔区域无亮条 | ☐ |
| C8 | 横屏（旋转屏幕） | 遮罩仍铺满，浮球位置不跑出屏幕 | ☐ |
| C9 | 切到别的应用、打开微信/相机 | 遮罩仍在最上层（相机预览会被压暗，属正常） | ☐ |
| C10 | 关闭开关 | 遮罩立刻消失、通知消失、状态回到「● 已关闭」 | ☐ |

## D. 安全逃生（重点验证，别怕）

| # | 检查点 | 期望 | 结果 |
|---|---|---|---|
| D1 | 「安全触摸上限」关掉（有二次确认）→ 上限选 `95%` → 滑到 85% | 屏幕明显更暗，**桌面上触摸可能失效** | ☐ |
| D2 | 此时浮球是否自动出现 | 应该自动出现在屏幕右侧（即使「浮球调节」是关的） | ☐ |
| D3 | 拖浮球向下 | 亮度被调回，触摸恢复 | ☐ |
| D4 | 再次调到 85% 后，下拉通知栏点「关闭」 | 遮罩关闭，一切恢复 | ☐ |
| D5 | 再调到 85% 后，点控制中心「极暗」磁贴 | 遮罩关闭 | ☐ |
| D6 | 重新打开「安全触摸上限」，滑条上限回到 80% | 正常 | ☐ |

> D2/D3 是「>80% 触摸被拦」时的唯一软着陆方式，务必确认可用；如果浮球也被拦（极端情况），用通知栏或磁贴关闭。

## J. 深度模式（无障碍图层，进阶，决定能否真正突破 80%）

> 这组是 1.0 里唯一依赖「无障碍服务」的路径，风险最高，请务必逐项记录。
> 前置：先按第 3 节开启悬浮窗/通知/电池/自启动，然后打开「深度模式（进阶）」开关。

| # | 检查点 | 期望 | 结果 |
|---|---|---|---|
| J1 | 打开深度模式开关 | 自动跳到系统「无障碍」页面；列表里能找到「极暗」 | ☐ |
| J2 | 在无障碍里开启「极暗」 | 出现 HyperOS 风险提示/倒计时，同意后服务连上；返回应用，副标题变「✅ 已生效」，上限放开到所选值 | ☐ |
| J3 | 深度模式开启后把滑条拉到 85% | 屏幕均匀压暗（**连状态栏、导航栏一起变暗**），且**任意应用仍可正常点击/滑动** | ☐ |
| J4 | 深度模式下拉到 95% | 极暗但仍能看清轮廓；触摸依然可用；**不应出现完全黑屏** | ☐ |
| J5 | J3/J4 状态下打开微信/浏览器/输入法 | 输入法可正常弹出使用；键盘区域也被压暗（无障碍层在 IME 之上） | ☐ |
| J6 | 深度模式 + 不透明度 >80% 时看浮球 | 浮球**不应被压暗到看不见**（应显示在深度层之上）；拖动浮球仍能调亮度 | ☐ |
| J7 | 在深度模式下关掉系统无障碍里的「极暗」 | 应用应**自动退回普通模式（≤80%）**并给出提示，不能变成「UI 说已生效、屏幕却没压暗」 | ☐ |
| J8 | 开启深度模式后锁屏再亮屏 | 记录锁屏上遮罩是否出现、是否影响解锁（预期：可能覆盖，属待验证项） | ☐ |
| J9 | 深度模式下息屏 30 分钟后亮屏 | 无障碍服务是否被 HyperOS 关掉；若被关，应用是否已自动降级 | ☐ |
| J10 | 关闭深度模式开关 | 上限立即回到 80%（若安全触摸开着），压暗层消失，屏幕亮度恢复正常 | ☐ |
| J11 | 深度模式下重启手机 | 无障碍服务是否仍启用；遮罩是否恢复（可能需手动重新开启无障碍，属已知限制） | ☐ |
| J12 | 后台挂着深度模式玩 10 分钟游戏 | 不卡顿、不掉帧（无障碍层是静态纯色 Surface，开销应极低） | ☐ |
